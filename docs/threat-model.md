# Threat model (M1, extended in M2)

Assets: the private library (titles, ratings, notes), accounts, the owner's write access, the TMDB key.
Trust boundary: **the browser is untrusted.** Anything enforced only in JavaScript is a convenience, not security.

| #   | Threat                                                  | Control                                                                                                              | Status                                                        |
| --- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| T1  | Viewer edits or deletes the owner's library             | RLS: writes require `owner_id = auth.uid()` **and** `is_owner()`; one owner enforced by a unique index               | In DB and tested (PGlite, 26 checks); `next/` UI fails closed |
| T2  | UI grants write access when the role is unknown         | `resolveRole` returns `viewer` unless the profile is well-formed and exactly `owner` (12 malformed-input test cases) | Done in `next/`                                               |
| T3  | Another account sees the previous user's cached library | Per-user cache names; clear on sign-out                                                                              | Naming done; clearing in M3                                   |
| T4  | Secret shipped to the browser                           | `parseEnv` rejects secret-named `VITE_*` vars and service-role keys; CI greps the bundle                             | Done                                                          |
| T5  | Sync overwrites a newer edit                            | `expectedUpdatedAt` contract                                                                                         | Contract only (M3)                                            |
| T6  | Corrupt/unknown data written or displayed               | Strict Zod mappers throw on bad rows                                                                                 | Done                                                          |
| T7  | TMDB key abuse via the proxy                            | Proxy requires a valid Supabase session and an allow-list of paths                                                   | Rebuilt and tested in `next/api/tmdb.ts` (M5.1, see T31-T34)  |
| T8  | Account takeover                                        | Supabase Auth; current-password check for email/password change                                                      | Root app done; port in M3                                     |

Out of scope for M1: rate limiting, audit logs, error reporting (M4).
| T6 | A stored link executes script when clicked (`javascript:`, `data:`) | Writes accept only `http(s)` URLs (`isHttpUrl`); rendering links only `http(s)` and shows anything else as plain text, with `rel="noopener noreferrer"` | Done in `next/`. The old app never validated this, so legacy rows may hold such values: they are readable but never become links |
| T7 | A stale tab silently overwrites a newer edit | Version check in the repository; the form keeps its opening version; conflict is an explicit user choice | Enforced by the mock; the real repository must enforce it in M3 (`expectedUpdatedAt` in the update `WHERE`) |
| T8 | A viewer reaches write screens by URL | `/library/new` and `/:id/edit` render an explanation, not a form; the repository refuses the write regardless | Done (UI and mock repository); RLS remains the real control |
| T9 | Account B sees account A's cached library after a switch | Private query keys include the user id; `PrivateCacheGuard` removes other accounts' queries; per-account repository and cache name | Done in the mock (tested); real sign-out/clear wiring in M3 |
| T10 | Unsaved edits lost by Back/Forward or a stray click | Router-level guard plus `beforeunload` | Done (tested for every exit) |

## M4 additions

| #   | Threat                                                                     | Mitigation                                                                                                                                                                                                           | Status                                                                                                                |
| --- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| T23 | Someone with the browser profile reads the saved library                   | One database per account; deleted on sign-out, revocation and account change; 30-day maximum age. Not encrypted: a key stored beside the data adds nothing                                                           | **Accepted, documented.** Same boundary as the stored refresh token. Sign out on shared computers                     |
| T24 | The app treats a person as signed in without the server confirming         | Stored identity restores _display only_: role unverified (viewer), writes hidden and refused, RLS unchanged; first server contact decides; revoked → sign-out + wipe                                                 | Done, tested (unit, integration, Chromium)                                                                            |
| T25 | A corrupt, tampered, outdated or foreign snapshot is shown                 | Format version, user id, row count, per-row schema validation, checksum over every persisted field, max age, future-date check; rows without a meta record; any doubt deletes the database and loads from the server | Done, tested and mutation-tested (a change to any one of the 15 data fields is caught; missing meta deletes the rows) |
| T26 | The service worker stores private or auth data                             | App shell only; never writes a runtime response; ignores cross-origin, `/api/*` and non-GET; Cache Storage scanned in Chromium for titles, email, user id, tokens                                                    | Done, mutation-tested                                                                                                 |
| T27 | A bad deploy strands users on a broken worker                              | Atomic install (any failed or redirected file keeps the old worker); no forced activation; `sw.js` is `no-cache`; documented kill-switch worker                                                                      | Done; the kill switch is a procedure, not code                                                                        |
| T28 | A stale saved copy is used to overwrite newer data                         | Writes are online-only and hidden while the copy is shown; `expectedUpdatedAt` is enforced in the `UPDATE`'s `WHERE`; a stale edit becomes a conflict                                                                | Done, tested across two devices on real Postgres                                                                      |
| T29 | A late answer or save lands after a newer one, or in the wrong account     | Per-account generation + monotonic `takenAt`; in-transaction "newer wins"; `isCurrent()` before and after every await                                                                                                | Done, 3 mutants killed                                                                                                |

T3 and T19 are now fully closed: the release-gate test scans IndexedDB (every database, every row) as well as the screen,
the query cache, localStorage and sessionStorage.

## M5.1 additions

| #   | Threat                                                     | Mitigation                                                                                                                                                                                                                   | Status                                                                                         |
| --- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| T31 | The TMDB proxy is used by anyone, or as an open relay      | Signed-in callers only (checked against this deployment's own Supabase project); GET only; two path patterns; per-route parameter allow-list; adult forced off; 100-character query; 1 MB answer limit; 8 s timeout          | Done, 34 unit tests, 13 mutants killed. **No rate limiting of our own** (TMDB's limit applies) |
| T32 | The TMDB key leaks                                         | Server variable without `VITE_`; never in a browser bundle (`check:bundle`); never in a URL when a v4 token is used; redacted from answers and errors; a wrong key is reported as 502, never 401                             | Done, tested                                                                                   |
| T33 | Poster lookups reveal one account's library to another     | Keys contain titles, so they live only in the account's own database, wiped with it; in-memory copies sit under the private query key; in-flight sharing is per account; release gate scans history and lookups in IndexedDB | Done, tested (integration, release gate, Chromium)                                             |
| T34 | A hostile or broken TMDB answer harms the app              | zod validation; poster paths must match `/[\w.-]+`; trailer ids must match `[\w-]{6,20}`; only `https://image.tmdb.org` and `youtube.com` URLs are built, from those fields; links open with `noopener noreferrer`           | Done, tested                                                                                   |
| T35 | Image requests expose the visitor's IP and viewing to TMDB | `referrerpolicy=no-referrer`; nothing about the account is sent; images are not cached by the service worker                                                                                                                 | **Accepted, documented.** Same exposure as any site showing TMDB posters                       |
| T36 | A temporary TMDB failure is remembered as "no poster"      | Failures are never stored; the query errors and is retried on the next visit; "not configured" and "rate limited" pause lookups for 5 minutes and 30 seconds                                                                 | Done, tested                                                                                   |

## M6 additions (offline editing, import/export, cutover, hardening)

| #   | Threat                                                                                  | Mitigation                                                                                                                                                                                                  | Status                                              |
| --- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| T50 | An offline edit silently overwrites a newer edit made elsewhere                         | Every queued edit/delete carries the version the person saw (`baseUpdatedAt`) and is sent with the same `expectedUpdatedAt` check as an online edit; a stale one is flagged "Needs review", never auto-resolved | Done; unit, real Postgres (PGlite) and full-app tests |
| T51 | Replaying a queued change twice duplicates or destroys data (reply lost, retry, 2 tabs) | One entry per title (coalesced); a create carries a client-chosen id, so a repeat is a primary-key conflict recognised as "already saved"; an edit whose values are already on the server counts as done; deleting something already gone counts as done; single-flight sender | Done; "lost reply" tested against fault injection   |
| T52 | An account that was demoted (or is a viewer) applies queued writes after reconnecting   | The server (RLS) decides at replay: refused changes are kept and shown for review, never dropped or retried forever. The offline role (last confirmed role, max 30 days) is a UI convenience used only when the role lookup fails with a network error | Done; tested with a demoted owner against real RLS  |
| T53 | Unsent private changes survive on the device after sign-out / are lost without warning  | Queue lives in the account's own database and is wiped with it. Signing out with unsent changes asks first ("Stay signed in" / "Sign out and discard them"). A damaged saved library no longer wipes the queue | Done. **Open decision:** a server-side (involuntary) sign-out still discards unsent changes |
| T54 | Account A's queued changes are sent as account B                                        | Per-account database; flush checks `isCurrent()` before and after every request; account change stops the run                                                                                              | Done; tested (switch during send)                   |
| T55 | A hostile or broken import file harms the library or the machine                        | Import only **adds** (never overwrites or deletes); preview first; 5 MB / 10,000-row caps; every row validated by the same schema as the form; duplicates (incl. F9 spelling, F2 year-less) skipped and listed; a JSON backup's checksum is checked and a mismatch is shown before anything is added | Done, tested                                        |
| T56 | A spreadsheet opened from an export runs a formula (CSV injection)                      | Cells starting `= + - @ tab CR` are prefixed so they are text                                                                                                                                              | Done, tested                                        |
| T57 | The cutover damages or loses production data                                            | Source only ever READ; destination guard refuses the production project; backup with SHA-256; read-only integrity gate (13 checks) with an "identical to this backup" proof; rollback table; no concurrent old-app writers | Tooling done and tested on dev; **production run is yours** (`cutover-runbook.md`) |
| T58 | Injected script loads code, or sends data, anywhere it likes (XSS impact)               | Content-Security-Policy: scripts only from this site, no inline/eval; connections only to this site and Supabase; images from this site and TMDB. Zod fast path (needs `eval`) disabled                      | Done; zero violations in real Chromium; see `hardening.md` limits |
| T59 | The site is framed (clickjacking) or reached through a window handle                    | `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`                                                                                                              | Done, tested                                        |
| T60 | The TMDB proxy is hammered (quota drain, auth-server fan-out)                           | Per-address limit before the sign-in check, per-user limit after it, 429 + Retry-After, capped tables                                                                                                      | Done per instance; **not global** (add a Vercel Firewall rule) |
| T61 | Error reports leak library or account data                                              | Reports have fixed fields; scrubbed message/stack; thrown non-errors never copied; paths stripped of ids/queries; dedupe + 20-per-load cap; no sink unless one is registered                              | Done, tested                                        |
| T62 | A blank page after a crash hides the problem and strands the user                       | App-level error boundary (plain markup, Reload) in addition to the per-screen error screen                                                                                                                | Done, tested                                        |
| T63 | A compromised dependency                                                                 | Not mitigated by CSP. Lockfile installs; `npm audit` in CI recommended                                                                                                                                      | **Accepted residual risk**                          |
